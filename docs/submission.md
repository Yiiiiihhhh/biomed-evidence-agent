# BioMed 循证文献工作台

## 项目定位

AI+X 中的 X 是生物医学研究。目标用户是需要做课题准备、课程综述或跨学科资料整理的学生与早期研究者。

对应[天猫OPC孵化赛道初赛](https://www.tuotuzju.com/hackathon/2/challenges?track=campus&stage=initial)的医学/教育场景。官网允许自由命题，强调真实需求、可验证产品与转化潜力；医学方向要求可靠来源与专业复核。初赛页面显示截止10月18日17:00，已于2026年10月15日核实。

核心痛点不是“写不出一段像综述的文字”，而是研究者需要反复核对论文是否真实、引用是否正确、结论来自摘要还是全文，以及模型的表述能否回到原文。BioMed 将这条核对链做成可操作的网页工作流。

## 解决方案与差异

1. **先查来源，再让模型阅读。** PubMed / Europe PMC 提供题录，Crossref 用于 DOI 身份核对；模型不能自行生成参考文献记录。
2. **让证据约束输出。** 每条证据保存研究问题、发现、原文引文、文献编号与依据层级，完整引文经过归一化匹配。模型生成的论断必须关联有效证据编号，由程序统一渲染引用。
3. **失败也形成可复查记录。** 账户余额不足、来源超时、字段差异和无有效证据都有明确状态。检索成功不会掩盖阅读失败。
4. **降低第一次体验的门槛。** 免费检索和引用核验无需模型密钥；AI 阅读采用用户自带密钥。匿名空间隔离记录，支持分步保存与导出。

这些是工作流与工程实现上的设计取舍，不宣称独占技术或自动消除幻觉。

## 作品已经做到什么

可独立运行的 React + Node 网页、SQLite 持久化、检索与身份核验、开放 XML 全文/摘要读取、证据约束 AI 草稿、历史记录与三种格式导出。提供完整源码、固定依赖锁文件、Dockerfile、魔搭配置与复现说明。

## 已取得的验证证据

2026年10月15日执行了 27 项核心与存储检查、21 个使用离线来源/模型 fixtures 的路由场景，以及16项本地HTTP检查。魔搭Docker已构建运行，浏览器免费检索选取3篇、3篇Crossref身份一致；PubMed命中704条、获取前40条，Europe PMC本次查询未完成，审计单独记录。正确引用返回通过，错误作者对照返回存疑。

此前真实接口复测曾遇到两个来源同时超时，系统明确返回SEARCH_FAILED并保留任务，公开接口稳定性仍需改善。云端重新部署后原会话仍保留研究，新标签页不显示原记录。这些数量不是文献筛选准确率或AI科学解释准确率。真实付费AI阅读、多用户负载、线上导出落盘和完全未登录访客仍待验收，不能把免费检索成功等同于AI综述有效。

## 使用场景

一名医工交叉学生提出“STAT1 在病毒感染中的负反馈机制是什么”。他先以英文词查询近期文献，检查 DOI 字段差异，再对身份一致的资料进行阅读取证。导出的证据矩阵保留原文，便于导师或同学逐条复查。最终草稿始终标为需要人工复核，不替代系统综述或临床判断。

## 可持续方向

先在研究方法课程、小型课题组和医工交叉教学中验证需求，收集真实使用时间、人工核对一致性与证据拒收原因。之后再考虑机构工作空间、团队复核、成本统计与受控文献库。当前不虚构用户数量、商业收入、节省时长或临床效果。
